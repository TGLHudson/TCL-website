# Adding publications and references

The Papers page (`/papers/`) and the References page (`/references/`) are generated by Jekyll from two data files:

- `_data/papers.json`: the research behind the book, by theme.
- `_data/references.json`: every source the book cites, A to Z.

Edit the data files, never the generated lists in `papers.html` or `references.html`. You can edit them in the GitHub web editor (open the file, press the pencil icon). Once the change is merged into `main`, GitHub Pages rebuilds the site.

JSON is strict: every field name and text value goes in straight double quotes, items are separated by commas, and there is no comma after the last item in a list. If the site stops updating after an edit, a stray or missing comma is the usual cause; GitHub shows the error on the repository's Actions tab.

## 1. Find and test the DOI

Every published paper needs a Digital Object Identifier (DOI), the permanent link to it.

- **Society of Petroleum Engineers (SPE) papers.** The DOI is `10.2118/` followed by the paper number and its suffix: SPE-220464-MS is `10.2118/220464-MS`. Journal papers end in `-PA`, for example `10.2118/27846-PA`. Check it on the paper's page in OnePetro (onepetro.org).
- **Journal articles and book chapters.** The DOI is on the first page of the article and on the publisher's page. If you cannot find it, search the title at [search.crossref.org](https://search.crossref.org).
- **Always test it.** Paste `https://doi.org/` followed by the DOI into a browser. It should open the paper's page.

## 2. Add a paper to the Papers page

Open `_data/papers.json`. It is a list of themes, each with an `id`, a `heading`, an `intro` and a list of `papers`:

| Theme | `id` |
|---|---|
| Where the ladder comes from | `origins` |
| Structure: why the rungs sit where they do | `structure` |
| Risk space: what the work demands | `risk-space` |
| Skill: competence plus experience | `skill` |
| Barriers and the bowtie | `barriers` |
| Incidents, non-compliance and a fair culture | `learning` |
| Decisions under pressure and emergency response | `decisions` |
| Choosing tools that fit | `tools` |

Copy an existing paper in the right theme, paste it in date order, and change the values:

```json
{
 "authors": "Hudson, T. G. L. & Hudson, P. T. W.",
 "year": "2027",
 "title": "Title exactly as published",
 "source_html": "SPE International Health, Safety, Environment, and Sustainability Conference and Exhibition, Abu Dhabi",
 "spe_number": "SPE-123456-MS",
 "doi": "10.2118/123456-MS",
 "in_press": false,
 "hudson": true,
 "doi_basis": "checked on OnePetro",
 "cited_in": ["the-culture-ladder"],
 "verified": true
}
```

- **`title`**: exactly as published. Do not expand acronyms or change spelling inside a title.
- **`source_html`**: where it appeared. For a journal, put the journal name in `<i>…</i>`: `"<i>Safety Science</i>, 45 (6), 697–722"`. Write `&` as `&amp;` here.
- **`spe_number`**: the SPE number, or `null` for anything else.
- **`in_press`**: `true` holds the paper back from the page. The brief lists published work only; set it to `false` once the paper is in OnePetro or the journal.
- **`hudson`**: `true` shows the *Request a copy* link. Use it only for papers by the Hudsons.
- **`cited_in`**: which books cite it. Today always `["the-culture-ladder"]`; later books get their own identifier.

The count of papers and themes at the top of the page updates itself.

**A new theme**: copy a whole theme (from `{ "id"` to its closing `}`), give it a new `id` (lower case, hyphens), a `heading` and an `intro` of one or two sentences, spelling out any acronym in full. The theme list and the alternating backgrounds follow automatically.

## 3. Add a source to the References page

Open `_data/references.json`. It is one list in A to Z order by the first author's surname ("de Ruijter" files under R). Copy a neighbouring entry, paste it in order, and change the values:

```json
{
 "letter": "M",
 "authors": "Surname, I. & Other, A.",
 "year": "2027",
 "title": "Title exactly as published",
 "source_html": "<i>Safety Science</i>, 150, 1–12",
 "type": "journal",
 "link": "doi",
 "doi": "10.1016/j.ssci.2027.01.001",
 "url": null,
 "host": null,
 "doi_basis": "checked at doi.org",
 "url_kind": null,
 "book_note": null,
 "cited_in": ["the-culture-ladder"],
 "check": null,
 "verified": true
}
```

- **`letter`**: the first letter of the surname, in capitals. A new letter appears in the A to Z bar by itself.
- **`link`** decides what the entry shows:
  - `"doi"`: a DOI link. Fill in `doi`.
  - `"free"`: a link to a free copy. Fill in `url` and `host` (the site's name, for example `"csb.gov"`). Only link a copy from the body that issued it, an official archive or an open-access publisher; never Scribd, Academia.edu, ResearchGate uploads or similar.
  - `"book"`: shows "Book", no link.
  - `"none"`: shows "Not freely available online".
- **`type`**: `journal`, `chapter`, `book`, `report`, `conference`, `thesis`, `legislation`, `web` or `other`.
- **`check`**: anything still uncertain, in plain words, or `null`.
- **`verified`**: `true` once you have opened the link and confirmed it is the right work.

The counts at the top of the page update themselves.

## 4. Check before merging

- Preview the site (see the README), or merge and check the live page.
- Click every new link.
- The rules in [CLAUDE.md](../CLAUDE.md) apply: British spelling in intros, no unpublished manuscript text, nothing confidential, published work only on the Papers page.
